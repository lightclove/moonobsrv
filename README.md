# moonobsrv

Телеграм-бот на чистом Zig (без единой внешней зависимости): мониторит **холостую Луну** (Void of Course), **ретроградный Меркурий** и **лунные дни**, присылает уведомления о переходах. Вся астрономия считается локально — ряды Meeus и кеплеровские элементы, никаких внешних API.

Прод — docker compose из трёх слоёв (**bot + postgres + tor**) на Arch-хосте в локальной сети; связь с Telegram — **через Tor** (SOCKS5, мосты obfs4). Операционный контур как у rbot: `/monitor`, послойные рестарты, стоп-краны, idle-статистика, обучающий визард, заявки на доступ кнопками.

История версий — [docs/CHANGELOG.md](docs/CHANGELOG.md), хронология разработки — [docs/TIMELINE.md](docs/TIMELINE.md), большой обзор проекта (все фичи, цифры, архитектура, как изучать) — [docs/OVERVIEW.md](docs/OVERVIEW.md).

## Найти и запустить бота в Telegram

Живой бот уже крутится на проде (Arch, через Tor) — это **[@moonobsrv_bot](https://t.me/moonobsrv_bot)**.

1. Откройте `t.me/moonobsrv_bot` в Telegram (или найдите `@moonobsrv_bot` в поиске) и нажмите **Запустить** — либо просто напишите `/start`. Бот ответит приветствием с кнопками: «🚀 Открыть обучающий гид», «📚 Оглавление», «☰ Меню команд».
2. Первые команды для пробы:
   - `/voc` — холостая Луна сейчас и ближайший период;
   - `/mercury` — ретро-Меркурий и тени;
   - `/day` — какой лунный день, знак и фаза Луны;
   - `/voc 21.09` — то же на конкретную дату;
   - `/wizard` — обучающий гид из 22 слайдов (3 админских слайда видит только владелец).
3. Хотите уведомления о событиях — `/subscribe` (отписка `/unsubscribe`). Проверить, что бот жив: `/status` (там же виден ваш id).
4. Доступ: пока на проде не задан `TELEGRAM_ACCESS_ID`, бот отвечает всем (режим разработки). Как только id владельца вписан в `~/Work/moonobsrv/.env` на Arch, новые пользователи попадают на заявку: админу приходит карточка с кнопками **Пустить / Отклонить**.

Запустить свою копию локально не сложнее — соберите проект и подставьте токен от [@BotFather](https://t.me/BotFather) (следующий раздел). Один токен = один работающий инстанс: если бот уже запущен на проде, локальная копия с тем же токеном получит от Telegram ошибку 409 и завершится.

## Быстрый старт

Тулчейн Zig 0.15.2 вложен в проект (`tools/zig-0.15.2/`, в `.gitignore`), сборка самодостаточна. Обёртка `z.cmd` берёт `zig` из PATH, а если его нет — из `tools/`:

```bat
z.cmd build test                  :: юнит-тесты + астрономические якори
z.cmd build -Drelease             :: релиз (ReleaseSmall, минимальный размер)
zig-out\bin\moonobsrv.exe --today :: офлайн-сводка на сейчас, без сети
```

Запуск бота (токен от @BotFather):

```bat
set TELEGRAM_TOKEN=123456:ABC
zig-out\bin\moonobsrv.exe
```

**Деплой на прод (Arch 192.168.31.11:22022, ключ `~/.ssh/id_ed25519_arch`, параметры из `netaccess/.credentials`):**

```bat
deploy.cmd            :: тесты → linux-musl бинарь → tar → scp → remote-apply.sh
deploy.cmd -Status    :: compose ps + хвост логов бота
```

`remote-apply.sh` на Arch: бэкап БД → `docker compose up --build -d` → ожидание контейнера бота. Токены живут только в `~/Work/moonobsrv/.env` на проде (0600), в тарбол не попадают.

## Команды бота

### Астрономия (всем)

| Команда | Псевдонимы | Что делает |
|---|---|---|
| `/voc` | `/void`, `/холостая` | холостая Луна сейчас + ближайший период, аспекты |
| `/mercury` | `/retro`, `/меркурий` | ретро-Меркурий сейчас и ближайшие периоды с тенями |
| `/day` | `/moon`, `/луна` | лунный день, границы, знак и фаза Луны |
| `/planets` | | долготы всех классических планет, пометка ретро |
| `/subscribe` | `/sub`, `/подписка` | уведомления о переходах (VOC, станции, лунные дни) |
| `/unsubscribe` | `/unsub`, `/отписка` | отключить уведомления |
| `/wizard` | `/guide`, `/гид` | обучающий гид по слайдам с кнопками |
| `/start` `/help` | | приветствие + кнопки (гид, оглавление, меню команд) |
| `/status` | `/stat` | аптайм, ваш id, подписчики, настройки |

Астрологические команды принимают дату: `/voc 21.09`, `/day 2026-09-21`.

### Слои и доступ (только админ — `TELEGRAM_ACCESS_ID`)

| Команда | Что делает |
|---|---|
| `/monitor` | живой срез: процесс, postgres, telegram, tor, wan, docker, диск, RAM, CPU, питание, sshd |
| `/restart` | принудительно все: postgres → tor → процесс бота |
| `/restartbot` `/restartpostgres` `/restarttor` | по одному слою (docker.sock, Engine API) |
| `/restarttelegram` `/restartwan` `/restartdocker` `/restartdisk` | не процессы — честный отказ |
| `/reset` (`/flush`) | стоп-кран: подтвердить всю пачку Telegram, `/restart` из неё не выполнять |
| `/hardreset` (`/hard`) | то же + один рестарт процесса бота |
| `/idlehour` `/idle3` `/idle5` `/idle8` `/idle12` `/idle24` `/idleday` `/idlenight` `/idleweek` `/idlemonth` `/idleyear` | простой слоёв за окно (снимки раз в минуту в Postgres), опечатки `/idel*` тоже работают |
| `/users` `/revoke <id>` | whitelist: список и отзыв доступа |

**`/restart` · `/reset` · `/hardreset` — не синонимы** (детально — в визарде, админские слайды):
- `/restart` дёргает слои и убивает процесс; очередь Telegram не сбрасывает; ACK до смерти — иначе бутлуп;
- `/reset` сбрасывает очередь, процесс живой, аптайм не сбрасывается;
- `/hardreset` = `/reset` + один docker-restart контейнера бота.

Анти-бутлуп: ACK (`getUpdates timeout=0`) до любого рестарта, курсор в файле + Postgres, inflight-«яд» на случай смерти посреди апдейта, стоп-кран просматривает пачку целиком до выполнения любого `/restart`, replay-команды старше процесса пропускаются, кулдаун рестартов 90 с.

### Доступ

Бот закрытый (когда заданы `TELEGRAM_ACCESS_ID` и БД): новый человек пишет `/start` — админу приходит карточка с кнопками **Пустить / Отклонить**; повторные заявки не спамят. `/subscribe` управляет только уведомлениями. Без БД (локальная разработка) бот открыт всем, админские команды отвечают отказом.

## Слои и Docker

```
docker-compose.yml           dev: bot + postgres (порт 5433 только на localhost)
docker-compose.prod.yml      прод: + tor (obfs4-мосты), БД без хост-порта,
                             MOONOBSRV_TOR=socks5://tor:9050
ci/tor/                      свой образ Tor: SocksPort 9050 для сети compose,
                             healthcheck = бутстрап 100% на control-порту
Dockerfile                   alpine + ca-certificates + статический musl-бинарь
```

- Бинарь кросс-компилируется на Windows: `z.cmd build -Drelease -Dtarget=x86_64-linux-musl` → `dist/moonobsrv` → тарбол → на проде ничего не собирается и не скачивается.
- Контейнер бота монтирует `/var/run/docker.sock` — так работают `/monitor` и `/restart*` (Docker Engine API сырым HTTP/1.0 над unix-сокетом, без библиотек).
- Healthcheck контейнера = свежесть heartbeat-файла `/tmp/moonobsrv.hb` (пишется каждый цикл; протух >300 с → контейнер нездоров). Внутри процесса watchdog: heartbeat молчит 300 с → trap → Docker поднимает.
- Tor без мостов поднимается не везде: `ci/tor/torrc` (с мостами, не коммитится) и `torrc.example` (шаблон). Мосты свои — как у rbot.
- После 3 подряд неудач getUpdates бот сам рестартует tor-контейнер (кулдаун 90 с) и шлёт админу алерт прямым каналом (в обход прокси), с повтором доставки.

### hostwatch (хостовый сторож)

`moonobsrv watch` — отдельный процесс на хосте (systemd, не контейнер): раз в минуту прощупывает docker-демон, контейнеры стека, Telegram через Tor, диск/CPU/питание/sshd. Дебаунс «два одинаковых среза подряд», алерты админу только на переходы («контейнер Tor упал» / «OK …»), первое стабильное состояние — сводка. Только sendMessage (getUpdates занят ботом).

## Архитектура

Три контура, зависимости строго вниз:

```
src/
├── main.zig              цикл polling: batch-brake → ACK → dedup → обработка;
│                         сэмплы слоёв раз в минуту; watchdog; CLI (watch/--today)
├── config.zig            конфиг из окружения (вкл. parseSocks)
├── dispatch.zig          маршрутизация одного апдейта: доступ → команды/колбэки
├── runtime.zig log.zig util.zig
│
├── net/                  ── свой транспорт вместо std.http.Client ──
│   ├── socks5.zig        SOCKS5-клиент (RFC 1928), домен в прокси = DNS в Tor
│   └── https.zig         TLS 1.3 (std.crypto) + HTTP/1.1 keep-alive поверх
│                         TCP или SOCKS5; таймауты на сокетах; один ретрай
│
├── db/pg.zig             клиент PostgreSQL wire-протокола v3: startup,
│                         trust/cleartext/md5, простой протокол (Q), без зависимостей
│
├── bot/
│   ├── telegram.zig      Bot API: sendMessage/editMessageText/answerCallbackQuery/
│   │                     клавиатуры, getUpdates+ack, 409 → exit(2), direct-алерты
│   ├── router.zig        реестр команд, контекст Ctx/Base
│   ├── store.zig         двойной бэкенд: Postgres (whitelist/подписки/kv/сэмплы/
│   │                     дедуп tg_inbox) или JSON-фолбэк; небесные флаги — всегда JSON
│   ├── wd.zig            сторож: heartbeat/bounce/inflight-яд/offset-файл, бэкофф,
│   │                     пробы tor/wan, Docker Engine API, рестарты контейнеров
│   ├── mon.zig           /monitor (текст), маски слоёв, idle-окна и статистика
│   ├── rst.zig           таргеты/план рестартов, стоп-краны, batch-brake, тексты
│   ├── access.zig        заявки на доступ, кнопки Пустить/Отклонить, whitelist
│   ├── cb.zig            роутер callback_query: wiz:* / menu:* / acl:*
│   ├── notify.zig webhook.zig
│
├── features/             горизонтальная нарезка: фича = команды + on_tick
│   ├── wizard.zig        гид: 22 слайда + 3 админских (вставка после «Шпаргалки»),
│   │                     прогресс-бар, оглавление 8/стр, меню команд
│   ├── monitor.zig       /monitor /idle* /restart* /reset /users /revoke
│   ├── voc.zig mercury.zig lunday.zig planets.zig service.zig
│   └── features.zig      реестр (команды собираются на компиляции)
│
└── astro.zig + astro/    чистое астроядро (без аллокатора): time/angles/sun/moon/
                          planets/aspects/voc/retro/lunday
```

Ключевые решения:

- **Астроядро чистое**: `f64 → f64`, без аллокатора — легко тестировать якорями по реальным событиям.
- **Свой HTTPS-клиент**: std.http.Client не умеет SOCKS; заодно выброшены пул/редиректы/чанкинг на все случаи — бот ходит ровно на один хост. Оба буфера сокет-писателя ≥ `tls.min_buffer_len` (~17 КБ) — TLS кладёт шифрокадр в буфер сокета одним куском; после flush TLS-писателя обязателен flush сокет-писателя.
- **Postgres без драйвера**: wire-протокол — это 4 кадра; одно соединение на процесс, один тихий ретрай на обрыв, таймауты на сокете.
- **Анти-бутлуп как в rbot**: ACK до рестарта, пачка getUpdates просматривается целиком (стоп-кран в хвосте отменяет /restart в голове), маркер рестарта + кулдаун, replay-фильтр по дате сообщения.

### Как добавить команду

1. Хендлер в любом файле `features/`:
```zig
fn cmdVenus(ctx: *router.Ctx) !void {
    const lam = astro.planets.longitude(.venus, astro.time.jdFromUnix(ctx.base.now));
    try ctx.reply.print("Венера: {d:.2}°", .{lam});
}
```
2. Элемент в `.commands` фичи — попадёт в `/help`, `setMyCommands` и цикл автоматически.

Для визарда: слайды в `features/wizard.zig` (`slides`/`admin_slides`), тесты следят за длиной <4096 и тем, чтобы пользовательские слайды не протекали админскими командами.

## Точность и соглашения

- **Луна** — 58 старших членов ELP2000 (Meeus 47): ±0.05°. **Солнце** — Meeus 25: ±0.01°. **Планеты** — кеплеровские элементы Standish (JPL, 1800–2050): угловые минуты.
- Моменты ингрессий/аспектов/станций — с точностью единиц минут модельного времени.
- **VOC** — классика: аспекты к видимым телам (Солнце…Сатурн). **Лунный день** — 30-я часть лунного месяца от новолуния.

### Проверено по реальным событиям (тесты в `src/tests.zig`)

| Якорь | Эталон | Факт |
|---|---|---|
| Солнечное затмение 12.08.2026 | 17:45:54 UTC | < 0.6° |
| Лунное затмение 03.03.2026 | 11:33 UTC | < 0.8° |
| Ретро-Меркурий 2026 (3 окна) + 2027 | станции по альманахам | ±36 ч |
| Ингрессия Луны 09.09.2026 | 22:36 МСК → Дева | 22:36 МСК |
| Лунный день 09.09.2026 | 28-й | 28-й |

Протокольные модули тоже покрыты тестами: кадры SOCKS5 и PostgreSQL (байт-в-байт + обмен с фейковым сервером на 127.0.0.1), маски/окна/статистика idle, batch-brake, клавиатуры (валидный JSON, callback_data ≤64 байт), тексты рестартов и стоп-кранов, дебаунс hostwatch.

## Размер бинарника

| Сборка | Размер |
|---|---|
| hello world (ReleaseSmall, strip) | 12 КБ |
| **moonobsrv linux-musl static (прод)** | **715 КБ** |
| moonobsrv.exe (Windows) | 803 КБ |

В бинарь вошли (поверх прежних 752 КБ): SOCKS5-клиент, TLS-over-SOCKS транспорт, wire-клиент PostgreSQL, визард (25 слайдов), мониторинг слоёв + Docker Engine API, стоп-краны, idle-статистика, hostwatch — а std.http.Client выброшен. Применено всё осмысленное: `ReleaseSmall`, strip, `omit_frame_pointer`, gc-sections, без libc (сетевой стек и консоль через syscall/WinAPI), `page_allocator`, проценты целыми, runtime-циклы вместо inline for в тригонометрических рядах. Пол — TLS-клиент из стандартной библиотеки (~420 КБ): проверка сертификатов токена ради безопасности. UPX при наличии дожмёт примерно вдвое.

## Ограничения и дорожная карта

- Один инстанс на токен (иначе getUpdates вернёт 409 — процесс завершается с кодом 2).
- `TELEGRAM_ACCESS_ID` на проде пока не задан: бот отвечает всем (режим разработки); впишите свой id (виден в `/status`) в `~/Work/moonobsrv/.env` на Arch и перезапустите — включатся заявки и админские команды.
- Идеи: команды с аргументами-периодами, приоритетные уведомления, версионирование схемы state.json.
