# moonobsrv

Телеграм-бот на чистом Zig (без единой внешней зависимости): мониторит **холостую Луну** (Void of Course), **ретроградный Меркурий** и **лунные дни**, присылает уведомления о переходах. Вся астрономия считается локально — ряды Meeus и кеплеровские элементы, никаких внешних API.

```
🌒 Луна не холостая
♌ Лев — пройдено 62% знака
• ✶ секстиль Венера — 9 сентября, 21:58

Ближайший холостой период: с 9 сентября, 21:58 (после аспекта секстиль Венера)
до входа в Деву (9 сентября, 22:36).

☿ Меркурий директен (ретроградности нет)
Ближайший ретро-период: 24 октября, 10:11 — 13 ноября, 18:51
Пред-тень с 4 октября, 11:58, пост-тень до 30 ноября, 09:04

🗓 Идёт 28-й лунный день
Начался: 8 сентября, 12:14. Луна ♌ во Льве, фаза: старая луна
```

## Быстрый старт

Тулчейн Zig 0.15.2 вложен в проект (`tools/zig-0.15.2/`, ~330 МБ, в `.gitignore`), поэтому сборка самодостаточна. Обёртка `z.cmd` берёт `zig` из PATH, а если его нет — из `tools/`:

```bat
z.cmd build test                  :: юнит-тесты + астрономические якори
z.cmd build -Drelease             :: релизная сборка (ReleaseSmall, минимальный размер)
zig-out\bin\moonobsrv.exe --today :: офлайн-сводка на сейчас, без сети
```

`zig build` молчит при успехе (печатает только ошибки), а при повторных запусках пропускает работу через кэш `.zig-cache`. Хотите видеть дерево шагов — добавьте `--summary all`; полная пересборка с нуля — после удаления `.zig-cache`.

Запуск бота (токен от @BotFather):

```bat
set TELEGRAM_TOKEN=123456:ABC
zig-out\bin\moonobsrv.exe
```

Если у вас стоит свой Zig 0.15.x в PATH — команды работают напрямую без обёртки: `zig build test`, `zig build -Drelease`. Кросс-компиляция штатная: `z.cmd build -Drelease -Dtarget=x86_64-linux`. Код написан под API ветки 0.15.x (`std.Io`, unmanaged `ArrayList`) — тулчейны других мажорных версий его не соберут без правок.

## Команды бота

| Команда | Псевдонимы | Что делает |
|---|---|---|
| `/voc` | `/void`, `/холостая` | холостая Луна сейчас + ближайший период, аспекты Луны |
| `/mercury` | `/retro`, `/меркурий` | ретро-Меркурий сейчас и ближайшие периоды с пред/пост-тенями |
| `/day` | `/moon`, `/луна` | какой лунный день, его границы, знак и фаза Луны |
| `/venus` `/mars` `/jupiter` `/saturn` | | знак планеты и ретро-движение: сейчас или на дату |
| `/subscribe` | `/sub`, `/подписка` | уведомления о переходах (VOC, станции Меркурия и планет, лунные дни) |
| `/unsubscribe` | `/unsub`, `/отписка` | отключить уведомления |
| `/status` | `/stat` | аптайм, подписчики, настройки |
| `/help`, `/start` | | справка (генерируется из реестра команд) |

Астрономическим командам можно передать дату: `/voc 21.09`, `/day 21.09.2026`,
`/mercury 2027-03-01` (форматы `ДД.ММ`, `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`; без аргумента — «сейчас»).
Список команд регистрируется в Telegram (`setMyCommands`) — работает автодополнение в клиентах.

Подписчики хранятся в `data/state.json` (атомарная запись через tmp+rename, схема версионируется полем `v`). При первом запуске состояние инициализируется текущим небом — спама «переходов» при старте нет.

## Режимы получения обновлений: polling и webhook

**Polling (по умолчанию).** Ничего настраивать не нужно. При старте бот снимает зарегистрированный webhook (`deleteWebhook`), чтобы режимы не конфликтовали.

**Webhook.** Включается заданием `MOONOBSRV_WEBHOOK_URL`. Telegram присылает обновления сам — меньше исходящих соединений и мгновенная доставка. Важно: **Telegram принимает только HTTPS с валидным сертификатом**, а стандартная библиотека Zig не умеет серверный TLS — поэтому бот слушает обычный HTTP на `MOONOBSRV_LISTEN` (по умолчанию `127.0.0.1:8080`) и становится за TLS-терминатор. Путь запроса проверяется по пути из `MOONOBSRV_WEBHOOK_URL`, а каждый запрос — по заголовку `X-Telegram-Bot-Api-Secret-Token` из `MOONOBSRV_WEBHOOK_SECRET` (то же значение уходит в `setWebhook`).

Минимальный терминатор на Caddy (сертификаты Let's Encrypt — автоматически):

```
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

`.env` для webhook-режима:

```
TELEGRAM_TOKEN=...
MOONOBSRV_WEBHOOK_URL=https://bot.example.com/tg/случайный-сегмент
MOONOBSRV_LISTEN=127.0.0.1:8080
MOONOBSRV_WEBHOOK_SECRET=длинная-случайная-строка
```

Диагностика: `moonobsrv --webhook-info` печатает ответ `getWebhookInfo`. Уведомления ватчеров работают в обоих режимах — за ними следит фоновый поток с периодом `MOONOBSRV_CHECK_INTERVAL`.

## Конфигурация: переменные окружения и .env

Приоритет источников: **реальные переменные окружения → `.env`-файл → значения по умолчанию**. Файл `.env` ищется рядом с exe и в текущем каталоге (или по пути из `MOONOBSRV_ENV`); формат — `KEY=VALUE` на строку, `#`-комментарии, значения можно брать в кавычки. Шаблон — `.env.example` (скопируйте в `.env` и впишите токен; `.env` уже в `.gitignore`).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TELEGRAM_TOKEN` | — | токен бота (обязателен в сервисном режиме) |
| `MOONOBSRV_DATA_DIR` | `data` | каталог состояния |
| `MOONOBSRV_TZ` | `3` | часовой пояс вывода, часов (`3`, `-5`, `5.5`) |
| `MOONOBSRV_POLL_TIMEOUT` | `25` | long polling, сек |
| `MOONOBSRV_CHECK_INTERVAL` | `60` | период проверки неба, сек |
| `MOONOBSRV_WEBHOOK_URL` | — | публичный https-адрес webhook (задан → режим webhook) |
| `MOONOBSRV_LISTEN` | `127.0.0.1:8080` | локальный адрес HTTP-сервера webhook |
| `MOONOBSRV_WEBHOOK_SECRET` | — | секрет webhook (сверяется с заголовком Telegram) |

## Архитектура

Три слоя, зависимости направлены строго вниз:

```
src/
├── main.zig              режимы (polling/webhook), фоновый поток ватчеров, CLI
├── config.zig            конфиг из окружения и .env
├── dispatch.zig          общая обработка обновлений (polling и webhook)
├── log.zig               логгер в stderr
├── envfile.zig           загрузчик .env
├── util.zig              даты (Хиннант), русское форматирование, плюрализация
├── runtime.zig           глобальное состояние процесса
│
├── astro.zig             ── хаб астроядра (чистые функции, без аллокаций) ──
│   └── astro/
│       ├── time.zig      Unix ↔ JD ↔ столетия J2000
│       ├── angles.zig    wrap180/360, бисекции, поиск нулей «пилы»
│       ├── sun.zig       долгота Солнца (Meeus, ±0.01°)
│       ├── moon.zig      долгота Луны (усечённый ELP2000, ±0.05°)
│       ├── planets.zig   гелио/геоцентрики по Кеплеру (Standish JPL)
│       ├── aspects.zig   птолемеевские аспекты
│       ├── voc.zig       холостая Луна: ингрессии + точные аспекты
│       ├── retro.zig     станции и тени ретро-периодов любой планеты
│       └── lunday.zig    лунные дни (30-е части лунного месяца)
│
├── bot/                  ── инфраструктура ──
│   ├── telegram.zig      минимальный Bot API-клиент (std.http + TLS 1.3)
│   ├── router.zig        реестр команд, контексты Ctx/Base
│   ├── store.zig         персистентность (JSON, атомарно, мьютекс)
│   ├── webhook.zig       HTTP-сервер приёма webhook'ов
│   └── notify.zig        рассылка подписчикам
│
└── features/             ── фичи: горизонтальная нарезка ──
    ├── features.zig      реестр: Feature = команды + опциональный on_tick
    ├── voc.zig           /voc + уведомления VOC
    ├── mercury.zig       /mercury + станции Меркурия
    ├── lunday.zig        /day + начала лунных дней
    ├── planets.zig       /venus /mars /jupiter /saturn + их станции
    └── service.zig       /start /help /status /subscribe
```

Ключевые решения:

- **Астроядро чистое**: `f64 → f64`, без аллокатора (буферы передаёт вызывающий) — легко тестировать, легко переиспользовать.
- **Фича = один файл**: команды и ватчер живут рядом, реестр собирается на компиляции.
- **Монотонность вместо грубого перебора**: сепарация Луна–планета за окно VOC строго растёт, элонгация Луны строго растёт — переходы через границы ищутся бисекцией по «пиле» wrap180 (шаг скана 29 минут, уточнение до секунд).
- **Один HTTP-клиент** с пулом соединений на весь процесс (потокобезопасный `fetch`); арены на тик/обновление.
- **Ватчеры — фоновый поток** поверх залоченного стора: уведомления о переходах не зависят от прихода обновлений и работают одинаково в polling и webhook.
- **Общий dispatch**: и polling, и webhook обрабатывают команды одной функцией (`dispatch.zig`).

### Как добавить команду (и ватчер)

1. Создайте `src/features/neptune.zig`:

```zig
const features = @import("features.zig");
const router = @import("../bot/router.zig");
const astro = @import("../astro.zig");

fn cmdNeptune(ctx: *router.Ctx) !void {
    const now = try ctx.moment(); // «сейчас» или дата из аргумента
    try ctx.reply.print("Нептун: {d:.1}°", .{astro.planets.longitude(.neptune, astro.time.jdFromUnix(now))});
}

pub const feature = features.Feature{
    .commands = &.{.{ .name = "/neptune", .description = "долгота Нептуна", .handler = cmdNeptune }},
    // .on_tick = ... — опциональный ватчер уведомлений
};
```

2. Допишите `const f_neptune = @import("neptune.zig");` и элемент в `all` в `src/features/features.zig`.

Готово: команда попадёт в `/help` и `setMyCommands` автоматически, ватчер — в цикл мониторинга. Для нового поля состояния добавьте его в `Persist` (`bot/store.zig`), `Flag` и инициализацию в `bootstrap`.

### Как добавить астрономическую сущность

В `astro/` новый файл с чистыми функциями + строка-экспорт в `astro.zig`. Для планеты ничего писать не надо — все от Меркурия до Плутона уже в кеплеровской таблице (`planets.elements`), ретро-механика (`retro.zig`) работает для любой.

## Точность и соглашения

- **Долгота Луны** — 58 старших членов ELP2000 (Meeus 47): ±0.05°.
- **Солнце** — Meeus 25: ±0.01°. **Планеты** — кеплеровские элементы Standish (JPL, валидны 1800–2050): угловые минуты.
- Моменты ингрессий/аспектов/станций — с точностью единицы минут модельного времени (ΔT игнорируется, ~1 мин).
- **VOC** — классическое определение: аспекты к Солнцу, Меркурию, Венере, Марсу, Юпитеру, Сатурну (видимые тела). Хотите «модерн» с Ураном–Плутоном — добавьте их в `planets.classical`.
- **Лунный день** — 30-я часть лунного месяца: N-й день начинается при элонгации (N−1)·12°, 1-й — в новолуние. Некоторые русские календари считают дни от восхода Луны (зависит от локации) — у них могут отличаться границы дня, номер совпадает.

## Размер бинарника

| Сборка | Размер |
|---|---|
| hello world (ReleaseSmall, strip) | 12 КБ |
| только std.http + TLS (зонд) | 421 КБ |
| **moonobsrv целиком (polling)** | **752 КБ** |
| **moonobsrv целиком (вебхук-сервер + потоки)** | **794 КБ** |

Применено всё, что имеет смысл:

- `-OReleaseSmall` (режим по умолчанию для `-Drelease`);
- `strip` — без символов;
- `omit_frame_pointer`; `-ffunction-sections -fdata-sections --gc-sections` — мёртвый код вычищается линкером (в релизе включено по умолчанию);
- без libc (сетевой стек и консоль через WinAPI), аллокатор `page_allocator`;
- проценты печатаются целыми, чтобы не тянуть форматирование дробных;
- runtime-циклы вместо `inline for` в тригонометрических рядах (без раздувания кода).

**Почему не десятки килобайт**: обязательный TLS-клиент (криптография, проверка сертификатов) из стандартной библиотеки занимает ~420 КБ — это пол любого приложения на std.http. Дальше ужиматься можно только ценой либо отказа от проверки сертификатов (небезопасно — токен бота), либо ручной реализации TLS 1.3 (уже не «чистый Zig из stdlib»). UPX, если он у вас есть, сжимает бинарник примерно вдвое.

## Ограничения и дорожная карта

- Один инстанс на токен (иначе getUpdates вернёт 409 / webhook будет перезаписан).
- Тексты ответов ≤ 4096 символов — обрезаются по границе UTF-8.
- Webhook-режим требует TLS-терминатор (серверного TLS в std нет) — caddy/nginx решают.
- Идеи: уровни подписок («только станции Меркурия» без лунных дней), уведомления «за 30 минут до начала VOC», эфемеридные таблицы взамен рядов для минутной точности, Web App для наглядных графиков.

Выполнено из дорожной карты: планеты `/venus /mars /jupiter /saturn` с уведомлениями о станциях, аргументы-даты для астрономических команд, webhook-режим, `setMyCommands`, версионирование схемы стора.
