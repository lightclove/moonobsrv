# BUG-043 — webhook: утечка памяти на каждый апдейт (экранированные строки parseUpdate)

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/webhook.zig` (арена на запрос вокруг parseUpdate+dispatch)
- Открыт: 2026-09-10
- Где найдено: код-ревью + зонд с DebugAllocator (утечка доказана)
- Серьёзность: средняя

## Симптом

В webhook-режиме каждый содержательный апдейт (текст с `\n`, кавычки в именах
— Telegram сериализует их с экранированием) оставлял аллокации в
page_allocator навсегда: под批评 parseUpdate (leaky) выделяет строки с
эскейпами из `alloc`, а освобождался только `body`.

## Причина

`handleRequest` парсил в `alloc` (= page_allocator из main), без арены; в
polling-режиме той же ошибки нет — там арена на пачку.

## Лечение

Арена на запрос: parseUpdate и dispatch работают в
`ArenaAllocator(alloc)`, деиницируемой после обработки.

## Профилактика

Код-ревью правило: parseFromSliceLeaky — только в арене. Юнит-проверка
утечки требует проброса аллокатора в HTTP-слой — отражено ревью.
