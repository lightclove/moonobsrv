# BUG-002 — буфер сокет-писателя меньше TLS-кадра

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: прод (диагностика MOONOBSRV_NET_DEBUG)
- Серьёзность: критическая
- Фикс: `src/net/https.zig` (буферы 17 КБ)

## Симптом

Бот зависал после «tls ок», до старта потоков: один поток, heartbeat
протухает, ни ошибок, ни таймаутов. На Windows-тестах не воспроизводилось
(там путь не доходил до прод-сценария).

## Причина

`std.crypto.tls.Client` пишет шифрокадр в буфер сокет-писателя одним
куском: `output.writableSliceGreedy(min_buffer_len)` требует ≥ ~16.7 КБ.
Буфер был 8 КБ. В Debug это assert, а в ReleaseSmall ассерты выключены —
UB вместо ошибки, отсюда «тихое» зависание без срабатывания таймаутов.

## Лечение

Все буферы соединения (сокет-чтение, сокет-запись, TLS-чтение, TLS-запись)
подняны до 17 КБ с комментарием-обоснованием в `net/https.zig`.

## Профилактика

Комментарий-мина у буферов + пункт в docs/OVERVIEW.md («минусы»):
собственный транспорт требует буферов ≥ tls.min_buffer_len. При апгрейде
Zig — сверять константу.
