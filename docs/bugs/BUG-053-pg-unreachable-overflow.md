# BUG-053 — pg: catch unreachable на данных конфигурации — UB вместо ошибки

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/db/pg.zig` (buildStartup → ?[]const u8 → PgBadUrl; cleartext-пароль > 255 → PgBadUrl; буферы расширены)
- Открыт: 2026-09-10
- Где найдено: код-ревью (ночной аудит протоколов)
- Серьёзность: низкая

## Симптом

Экзотически длинные user/database (startup, буфер [512]) или cleartext-
пароль > 95 байт (буфер [96]) — вместо ошибки `catch unreachable`:
паника в Debug, UB в ReleaseSmall (прод).

## Причина

Ошибка переполнения fixed-писателя гасилась unreachable на ровном месте,
хотя все соседние пути возвращают Error.

## Лечение

buildStartup возвращает null при нехватке буфера → connect возвращает
PgBadUrl; буфер пароля расширен до 256 с честной ошибкой сверх; md5-путь
(фикс. 35 байт) помечен как гарантированный.

## Профилактика

Тест buildStartup с 600-байтовым user → null. Правило: данные конфигурации
не «unreachable»-ся.
