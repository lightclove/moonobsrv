# BUG-004 — кадры PostgreSQL: обратный порядок байтов и +1 к длине

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: тесты (фейк-сервер на 127.0.0.1)
- Серьёзность: высокая
- Фикс: `src/db/pg.zig` (`buildTagged`, Terminate)

## Симптом

Рукопожатие с базой зависало: клиент ждал ответа, сервер ждал окончания
запроса. Сначала тесты вообще «зависали намертво» — первый намёк.

## Причина

Две ошибки знакомства с wire-протоколом: (1) кадр писался как
`[len][tag][payload]` вместо правильного `[tag][len][payload]`
(исключение — StartupMessage без тега); (2) длина считалась на 1 больше —
сервер ждал ещё байт, которого не будет. Тесты ловили не сразу: первая
паника в соседнем тесте убивала процесс раньше зависания, маскируя картину.

## Лечение

`buildTagged` пишет `[tag][len][payload]` с длиной `4 + payload`;
Terminate — `'X'` + int32 4.

## Профилактика

Тест «протокол: trust/md5-аутентификация и запрос» с фейк-сервером
прогоняет живой обмен кадр-в-кадр — теперь любая рассинхронизация ловится
на dev-машине, а не на проде. Рецепт: протоколы начинать с байт-в-байт
эталонов, потом живой обмен с актёром.
