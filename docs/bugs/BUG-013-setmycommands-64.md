# BUG-013 — потолок setMyCommands в 64 команды при лимите Telegram 100

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/main.zig` (буфер 100) + `src/features/features.zig` (comptime-лимит 100)
- Открыт: 2026-09-09
- Где найдено: код-ревью (обзор архитектуры)
- Серьёзность: низкая

## Симптом

При росте реестра команд больше 64 `registerCommands` молча обрежет
список (буфер `[64]Entry`), и часть команд не попадёт в автодополнение
Telegram. Компиляторный `@compileError` в `features.zig` вообще запрещает
сборку при >64 — то есть лишняя команда сломает билд раньше, чем обрежется.

## Причина

Буфер и проверка писались «с запасом» до того, как реестр разросся до 37;
запас оказался меньше реального лимита Telegram (100).

## Лечение (план)

Поднять буфер до 100 и выровнять компиляторную проверку с лимитом Bot API
(или разбить на несколько вызовов setMyCommands по scope, если захочется
больше). Тривиально, не срочно.

## Профилактика

Комментарий у буфера со ссылкой на лимит Bot API; при добавлении пачки
команд — смотреть на `commands.len` в логе запуска.
