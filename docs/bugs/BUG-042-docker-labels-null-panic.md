# BUG-042 — Docker «Labels»: null паникует разбор контейнеров (UB на проде)

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/wd.zig` (parseContainers/composeId/containerIp: проверка тегов Value) + тест с Labels:null
- Открыт: 2026-09-10
- Где найдено: код-ревью (ночной аудит; подтверждено зондом с паникой)
- Серьёзность: высокая

## Симптом

Один чужой контейнер без лейблов на хосте (`docker run` без `--label` — moby
присылает `"Labels":null`, nil-мапу не нормализует) ронял процесс при
`/monitor`, авто-рестарте Tor и каждом цикле hostwatch: доступ к `.object`
неактивного поля `std.json.Value` — паника в Debug, UB в ReleaseSmall (прод).

## Причина

`(obj.get("Labels") orelse continue).object` — orelse ловил только отсутствие
ключа; null и нестроковые значения (State/Status/Names/Id/лейблы) не
проверялись нигде в разборе.

## Лечение

Проверка тега перед каждым доступом (`if (v != .object/.string) …`), хелпер
`strOrNull`. Нестроковой лейбл сервиса → пустая строка, Names:null → имя «?».

## Профилактика

Тест «Labels null и нестроковые поля не роняют разбор» (фикстура с null,
числовым проектом, Names:null, строковым элементом массива).
