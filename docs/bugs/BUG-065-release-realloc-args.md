# BUG-065 — релизная сборка не компилировалась: realloc с лишним типом

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-12)
- Открыт: 2026-09-12
- Где найдено: деплой (гейт кросс-сборки linux-musl в `ci/deploy.ps1`)
- Серьёзность: высокая
- Фикс: `src/bot/wd.zig` — `arena.realloc(buf, cap)` (1.2.2)

## Симптом

`deploy.cmd` падал на шаге кросс-сборки, до tar/scp не доходило:

```
src\bot\wd.zig:290:24: error: member function expected 2 argument(s), found 3
    buf = arena.realloc(u8, buf, cap) catch return null;
```

`z.cmd build test` при этом зелёный — 99 тестов проходят.

## Причина

Фикс BUG-052 (рост буфера ответов Docker до 1 МиБ, ночная вахта 1.2.1)
вызвал `Allocator.realloc` по старой сигнатуре с явным типом: в Zig
0.15.2 метод — `realloc(old_mem: anytype, new_n: usize)`, тип выводится
из среза, лишний аргумент `u8` — ошибка компиляции. Тесты не поймали,
потому что Zig анализирует функции ленично: цепочка `main.zig →
monitor → dockerHttp` компилируется только в exe-сборке, а тестовый
корень (`src/tests.zig`) `dockerHttp` не дотягивается. Релизный бинарь
после вахты никто не собирал — 1.2.1 на прод не выкатывался.

## Лечение

`src/bot/wd.zig:290`: `arena.realloc(u8, buf, cap)` →
`arena.realloc(buf, cap)`. Других `realloc` в `src/` нет (проверено
поиском). Проверено: `z.cmd build test` и
`z.cmd build -Drelease -Dtarget=x86_64-linux-musl` — обе сборки зелёные.

## Профилактика

`ci/deploy.ps1` уже гоняет кросс-сборку до выката — гейт сработал как
задуман и не пустил несобирающийся код на прод. Правило на будущее:
после правок сетевых/админских путей, не покрытых тестовым корнем,
прогонять `z.cmd build -Drelease -Dtarget=x86_64-linux-musl` локально
до коммита — это единственная сборка, где ленивый анализ доходит до
всех функций exe.
