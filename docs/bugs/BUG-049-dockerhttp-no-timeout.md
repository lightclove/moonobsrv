# BUG-049 — dockerHttp без таймаута: зависший демон Docker навсегда паркует hostwatch

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/wd.zig` (SO_RCVTIMEO/SO_SNDTIMEO на unix-сокете; комментарий tcpProbe выровнен с кодом)
- Открыт: 2026-09-10
- Где найдено: код-ревью (ночной аудит сторожей)
- Серьёзность: средняя

## Симптом

Docker-демон принимает коннект по unix-сокету, но не отвечает (stopping/
deadlock — воспроизводимая ситуация) → блокирующий `stream.read` висит
вечно. В боте такой зависший вызов убивает watchdog-трап через 300 с, а в
`moonobsrv watch` watchdog-потока НЕТ: сторож молча замирает навсегда,
systemd считает его живым, алерты не приходят.

## Причина

Параметр `read_timeout_s` принимался и игнорировался (`_ =`; комментарий
«watchdog страхует» верен только для процесса бота).

## Лечение

setsockopt SO_RCVTIMEO/SO_SNDTIMEO на сокете Docker (как в https/pg).
Заодно комментарий tcpProbe приведён к事实чности: DNS-резолв идёт в потоке
вызывающего.

## Профилактика

Ревью-правило: любой блокирующий сетевой вызов — с таймаутом независимо от
наличия сторожа. Проверка socat-заглушкой — в чек-листе релиза.
