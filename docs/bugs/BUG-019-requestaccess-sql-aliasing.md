# BUG-019 — requestAccess: буфер экранированного имени затирается префиксом INSERT (SQL всегда битый)

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/bot/store.zig` (`writeRequestAccessSql`: имя и SQL в разных буферах) + тест
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA)
- Серьёзность: высокая

## Симптом

Даже когда `requestAccess` вызывается (после фикса BUG-018), INSERT заявки
падает синтаксической ошибкой Postgres: в VALUES вместо имени приходит
кусок самого префикса INSERT. Заявка не создаётся, `db_ok` сбрасывается
(что ещё и искажает /monitor и сэмплы).

## Причина

`src/bot/store.zig:403-409`: экранированное имя пишется во Writer на
`nb[0..400]`, затем второй Writer стартует с начала ТОГО ЖЕ буфера `nb` и
пишет туда префикс INSERT — затирая имя; финальный `writeAll(name_esc.buffered())`
копирует уже испорченные байты. Классический алиасинг буферов (та же
семья, что BUG-022/023).

## Лечение

Разнести буферы: имя — в `nb`, SQL — в отдельный буфер достаточного
размера (префикс ~95 + имя ≤400 + суффикс ~110 → 768 байт).

## Профилактика

Юнит-тест: собрать SQL тем же кодом (выделить сборку в чистую функцию
`writeRequestAccessSql`) с именем «Аня» и убедиться, что в строке есть
`'Аня'`, а не «INSERT I…». Плюс правило: один Writer — один буфер, ревью
на пары `fixed(&x)`/`fixed(x[..])` в одной функции.
