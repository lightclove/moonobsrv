# BUG-021 — setWebhook подписывается только на message: в webhook-режиме не приходят callback_query

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/bot/telegram.zig` (общий `allowed_updates_list` для polling и webhook) + тест
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA, TC-152)
- Серьёзность: высокая

## Симптом

В webhook-режиме (`MOONOBSRV_WEBHOOK_URL`) молча умирает вся кнопочная
функциональность: навигация гида, оглавление, «Закрыть», меню быстрых
команд и кнопки заявок «Пустить/Отклонить» — Telegram не присылает
callback_query, потому что webhook зарегистрирован с
`allowed_updates = ["message"]`. Сменалась документированной паритетности
режимов («команды одни и те же в обоих режимах»).

## Причина

`src/bot/telegram.zig:215`: в `setWebhook` захардкожен массив из одного
элемента, тогда как polling-режим (`allowed_updates_enc`, строка 14)
запрашивает `["message","callback_query"]`.

## Лечение

Один общий список `["message","callback_query"]` для обоих режимов.

## Профилактика

Тест: сериализация тела setWebhook содержит "callback_query" (массив
вынести в именованную константу и проверять её).
