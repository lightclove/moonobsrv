# BUG-046 — ретрай HTTPS-запроса дописывает новое тело к обрывку старого

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/net/https.zig` (shrinkRetainingCapacity(0) перед повтором; мёртвое поле read_timeout_s удалено)
- Открыт: 2026-09-10
- Где найдено: код-ревью (семантика Writer.Allocating доказана зондом)
- Серьёзность: средняя

## Симптом

Обрыв посреди тела (умерла Tor-цепочка после чтения k<N байт) → ретрай на
новом соединении → `out.written()` = k байт мусора + полный новый ответ:
getUpdates падал на парсинге, повторные POST могли дублировать сообщения.

## Причина

`request()` повторял `requestOnce(opts, out)` с тем же Allocating-писателем
без сброса — Writer.Allocating дописывает, не заменяет.

## Лечение

`out.shrinkRetainingCapacity(0)` перед повтором. Заодно удалено мёртвое
поле `RequestOptions.read_timeout_s` (никогда не читалось — таймаут живёт
в ensureConnected).

## Профилактика

Ревью-правило: повтор запроса = сброс выходного буфера. Юнит требует
фейк-TLS — покрывается ревью.
