# BUG-001 — краш-луп на первом сообщении (use-after-free в parseUpdates)

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: прод
- Серьёзность: критическая
- Фикс: коммит `9b25474` (`src/bot/telegram.zig`)

## Симптом

`/start` от пользователя — бот молчит. В логах цикл: «запуск → postgres →
setMyCommands → inflight-яд: прошлый процесс умер на N», где N растёт с
каждым нажатием. Контейнер при этом успевает показывать healthy. Docker
бесконечно перезапускает процесс.

## Причина

`parseUpdates` разбирал ответ `parseFromSlice` + `parsed.deinit()`, а наружу
отдавал `alloc.dupe(Update, …)` — копию **оболочек** структур. Строки
(`msg.text`, `from.first_name`, …) оставались в освобождённой арене парсера:
чтение `msg.text` — use-after-free → SIGSEGV. Баг молчал всё время, пока
боту никто не писал: в пустых пачках обновлений строк нет. Инфраструктура
«яда» (inflight) честно ловила каждое падение, но лечила следствие.

## Лечение

Парсинг `parseFromSliceLeaky` в арены вызывающего цикла (её время жизни —
ровно обработка пачки), с `allocate = .alloc_always`, чтобы строки не
ссылались и на буфер ответа.

## Профилактика

Регрессионный тест «строки живут в арены вызывающего»: после парсинга
затирает исходный буфер (`@memset(buf, 'X')`) и проверяет строки. Правило:
любой `parseFromSlice` + `deinit` + возврат строк из функции — подозрительный
паттерн, смотреть на время жизни срезов.
