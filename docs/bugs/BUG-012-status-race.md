# BUG-012 — /status читает число подписчиков без мьютекса

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/store.zig` (`subsCount()` под мьютексом) + `src/features/service.zig`
- Открыт: 2026-09-09
- Где найдено: код-ревью (обзор архитектуры)
- Серьёзность: низкая

## Симптом

Пока не наблюдался; теоретическая гонка: `/status` печатает
`store.subs.items.len` напрямую, а фоновый поток ватчеров в этот момент
может менять список (`addSub`/`removeSub`). При перестройке массива чтение
длины и данных может рассинхронизироваться.

## Причина

Унаследовано из 1.0.0, когда стор трогал один поток; с 1.0.1 у стора два
потребителя, но /status не переведён на метод с мьютексом.

## Лечение (план)

Заменить прямое обращение на метод-обёртку под мьютексом (по образцу
`subsSnapshot`), либо читать снапшот в буфер. Одна строка + тест не нужен
(гонка недетерминирована), но обёртка закрывает класс ошибок.

## Профилактика

Правило: доступ к полям стора извне — только через методы стора
(все они под мьютексом).
