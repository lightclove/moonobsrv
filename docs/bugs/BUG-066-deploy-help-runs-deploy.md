# BUG-066 — deploy.cmd --help запускал полный деплой прода

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-21)
- Открыт: 2026-09-21
- Где найдено: прод
- Серьёзность: средняя
- Фикс: `ci/deploy.ps1` — блок разбора `$args` до начала деплоя

## Симптом

`deploy.cmd --help` (запрос справки) молча запустил полный цикл выката:
тесты → кросс-сборка → tar → scp на Arch → `compose up --build -d`, контейнер
бота пересоздан. Оператор хотел узнать ключи, а получил незапланированный
деплой прода. То же с любой опечаткой в ключах (например `-Statuss`).

## Причина

Windows PowerShell 5.1 в режиме `-File` кладёт нераспознанные аргументы
в `$args` и продолжает выполнение (проверено на живом скрипте: `--help`
→ `args count: 1`). В `deploy.ps1` объявлены только `[switch]$SkipTest` и
`[switch]$Status`, блоков справки и валидации `$args` не было — незнакомый
аргумент игнорировался, скрипт шёл по основному пути. `%*` в `deploy.cmd`
передаёт всё как есть.

## Лечение

`ci/deploy.ps1`: сразу после `param()` — блок разбора `$args` (до печати
target и всех шагов):

- токены `--help` / `-help` / `help` / `-?` / `/?` / `?` — печатают usage
  (назначение, три ключа) и `exit 0`;
- любой другой нераспознанный аргумент — «unknown argument(s): …»,
  подсказка usage и `exit 1` — деплой не начинается.

Текст ASCII-only (Windows PowerShell 5 читает .ps1 без BOM как ANSI,
BUG-009). Поведение проверено на живом скрипте: `--help` → справка,
exit 0; `-Statss` → отказ, exit 1.

## Профилактика

Правило: ключи деплой-скрипта обрабатываются до первого побочного действия;
любой нераспознанный аргумент — остановка, а не игнор (в этом же роду
BUG-040: молчаливое продолжение цепочки выката). CI-теста нет — скрипт
живёт на dev-машине и ходит по SSH на прод; ручная проверка — два вызова
из PowerShell: `.\deploy.cmd --help` (справка, без выката) и
`.\deploy.cmd -Statss` (отказ, exit 1).
