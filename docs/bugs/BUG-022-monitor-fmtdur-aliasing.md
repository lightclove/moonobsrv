# BUG-022 — /monitor: «жив» и «heartbeat» печатаются из одного буфера — аптайм искажается

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/bot/mon.zig` (раздельные `dur_up`/`dur_hb`) + расширение теста fmtMonitor
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA, TC-145)
- Серьёзность: средняя

## Симптом

В /monitor строка «• процесс — OK · жив X · heartbeat Y назад» показывает
в обоих местах последнее значение (возраст heartbeat), причём первый
фрагмент — обрезка по длине первой строки: «жив 5 м» — с разрезанной
посередине UTF-8 руной (Telegram может отклонить сообщение целиком).
При аптайме 2 ч и свежем heartbeat админ видит «жив 5 м».

## Причина

`src/bot/mon.zig:64-65`: оба аргумента `w.print` — `util.fmtDur(&dbuf, …)`
в один и тот же `dbuf`; вычисляются до печати, второй вызов затирает
результат первого, а длина слайса осталась от первого вызова.

## Лечение

Два раздельных буфера (`dbuf1`/`dbuf2`).

## Профилактика

Расширить существующий тест fmtMonitor: started = now−7200, hb_age = 5 →
в тексте обязано быть «жив 2 ч» и «5 мин назад». Общее правило: в одном
print — один временный буфер на каждое {s}.
