# BUG-040 — deploy: неудача распаковки tar не останавливает выкат — применяется старый код

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `ci/deploy.ps1` (tar-неудача рвёт цепочку; chmod допускает отсутствие файлов)
- Открыт: 2026-09-10
- Где найдено: код-ревью инфра-контура (ночной аудит прод-слоя)
- Серьёзность: средняя

## Симптом

Если scp прошёл, а `tar -xzf` на Arch не удался (битый/обрезанный tgz, диск),
удалённая команда всё равно продолжала: `… && tar -xzf … && chmod … 2>/dev/null;
rm -f … && bash ci/remote-apply.sh` — разделитель `;` перед `rm` пропускал
дальше даже провал. remote-apply поднимал контейнеры из ПРЕДЫДУЩЕЙ распаковки,
а deploy.ps1 печатал «prod updated» с кодом 0: выкат старой версии, выданный
за успешный.

## Причина

`chmod … 2>/dev/null` возвращает ненулевой код при отсутствии .sh — его
простили через `;`, но вместе с ним простили и провал tar раньше по цепочке.

## Лечение

`(chmod … || true)` — прощается только chmod; tar остаётся строгим звеном
`&&`-цепочки: при его неудаче remote-apply не запускается, ssh вернёт
ненулевой код, deploy.ps1 упадёт с 'remote-apply failed'.

## Профилактика

Ручная проверка F6 (полный деплой) + сценарий «битый tgz → деплой обязан
упасть». Регресс-теста нет (внешние ssh/tar) — отражено в чек-листе релиза.
