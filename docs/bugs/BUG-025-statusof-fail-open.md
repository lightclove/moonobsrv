# BUG-025 — statusOf: fail-open при сбое Postgres — закрытый бот открывается всем

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/bot/store.zig` (statusOf: `.none` на ошибках — fail-closed) + `src/bot/access.zig` (честный отказ при лежащей БД)
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA)
- Серьёзность: средняя

## Симптом

Если Postgres лёг ПОСЛЕ старта (соединение в `self.db` осталось), любой
неизвестный пользователь проходит гейт доступа: `statusOf` на ошибке
возвращает `.active` → `handleUnknown` → `pass_through` → команда
исполняется. Для «закрытого клуба» это провал изоляции на время инцидента
БД.

## Причина

`src/bot/store.zig:366-367`: оба `catch return .active` (и на ошибке
печати в буфер, и на ошибке exec). Fail-open выбран по умолчанию без
явного решения.

## Лечение

Fail-closed: на ошибке возвращать статус «не польз» (вместе с BUG-018 —
вариант `none`, а в `handleUnknown` для случая неработающей БД отвечать
«сервис временно недоступен, попробуйте позже» вместо ложного «заявка
отправлена»). Админ и ранее разрешённые (кэш `active`) проходят и при
лежащей БД.

## Профилактика

Юнит-тест невозможен без фейк-PG на этом уровне — закрепить ручную
проверку: остановить контейнер БД, написать боту с чужого аккаунта —
ответ должен быть отказом, не исполнением команды (чек-лист релиза).
