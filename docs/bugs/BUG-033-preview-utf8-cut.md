# BUG-033 — карточка заявки: preview[0..200] режет UTF-8 посреди руны

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/bot/access.zig` (`cutUtf8` — откат к границе руны) + тест
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA)
- Серьёзность: низкая

## Симптом

Если сообщение пользователя длиннее 200 байт и граница попадает в
середину кириллической руны, карточка заявки админу уходит с битым UTF-8
(разрезанным байтом) — Telegram может отклонить sendMessage (400), заявка
не дойдёт.

## Причина

`src/bot/access.zig:80`: `preview = preview[0..200]` — байтовый срез без
выравнивания на границу руны (в `dispatch.sendReply` такое выравнивание
есть).

## Лечение

Откатываться назад до границы UTF-8 (как в sendReply):
`while (cut > 0 and (preview[cut] & 0xC0) == 0x80) cut -= 1;`.

## Профилактика

Тест чистой функции подрезки: строка из 201-байтной кириллицы → результат
валидный UTF-8 и ≤ 200 байт.
