# BUG-003 — flush TLS-писателя не отправлял данные в сокет

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: прод (диагностика MOONOBSRV_NET_DEBUG)
- Серьёзность: критическая
- Фикс: `src/net/https.zig` (двойной flush)

## Симптом

После исправления BUG-002 рукопожатие проходило («tls ок»), запрос
«отправлялся» — и бот навсегда зависал в чтении статуса. Сервер не отвечал,
потому что не получал запроса.

## Причина

`flush()` TLS-писателя только шифрует накопленное и **кладёт шифротекст в
буфер сокет-писателя** (`output.advance`). Вытолкнуть его в сокет — забота
вызывающего. Наш код делал flush только TLS-писателя — запрос не покидал
процесс.

## Лечение

После `w.flush()` (TLS) добавлен `self.stream_writer.interface.flush()`
(сокет). Для plain-режима повторный flush по пустому буферу безвреден.

## Профилактика

Правило для всех, кто поверх `std.crypto.tls.Client`: «flush TLS ≠ flush
сокета». Зафиксировано в комментарии кода и в docs/OVERVIEW.md.
