# BUG-039 — после отказа в доступе повторная заявка через /start невозможна

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/access.zig` (ветка `.denied`: молчание для обычных команд, повторная заявка на `/start`)
- Открыт: 2026-09-10
- Где найдено: код-ревью (сверка со слайдом гида «Доступ» при закрытии BUG-018)
- Серьёзность: средняя

## Симптом

Задокументированный поток (слайд «Доступ», wizard.zig:242): «После отказа —
„Доступ отклонён“; повторная заявка: снова /start». Фактически отклонённый
пользователь на ЛЮБУЮ команду, включая `/start`, вечно получал
«Доступ отклонён.» — повторная заявка не создавалась никогда, вернуться в
бот можно было только руками в БД.

## Причина

После фикса BUG-018 ветка `.denied` в `handleUnknown` стала достижимой, но
безусловно возвращала отказ — единственный путь к `requestAccess` (слот
`.none`) для отклонённого недостижим. Комментарий в `requestAccess`
(«denied: молча обновляем заявку») описывал мёртвую ветку.

## Лечение

`.denied`: обычные команды — молчание (порт механики rbot: «denied молчит
до /start»); `/start` — проваливается в путь заявки: статус обновляется в
pending, админ получает карточку (от спама защищает дальнейший pending).
Комментарий в `requestAccess` выровнен с фактическим поведением.

## Профилактика

Ручная проверка E3/E4 в MANUAL_TESTING.md (отклонить → молчание → /start →
новая карточка админу). Юнит без фейк-API не строится — отражено в
чек-листе релиза.
