# BUG-045 — UTF-16 .env крашит процесс на старте (WTF-8 assert → UB в релизе)

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/envfile.zig` (BOM UTF-16 → лог и пропуск; wtf8ValidateSlice ключа/значения) + тест
- Открыт: 2026-09-10
- Где найдено: код-ревью (ночной аудит протоколов; падение доказано зондом)
- Серьёзность: высокая

## Симптом

`.env`, сохранённый PowerShell 5.1 через `> .env` (по умолчанию UTF-16LE с
BOM FF FE), ронял процесс при загрузке конфига: `EnvMap.get` ассертит
валидность WTF-8 ключа — паника в Debug/ReleaseSafe, UB в ReleaseSmall (прод).
Кириллический комментарий модуля сам ссылается на PowerShell-практику.

## Причина

Фильтровался только UTF-8 BOM; ключ с байтами UTF-16 уходил в
`std.process.EnvMap.get` → `assert(wtf8ValidateSlice(key))` (std/process.zig:185).
Нулевой байт пары 0A 00 давал «строки», а не отказ.

## Лечение

BOM UTF-16LE/BE — лог «пересохраните в UTF-8» и пропуск файла; каждая
строка дополнительно валидируется wtf8ValidateSlice (ключ и значение) —
битые строки пропускаются молча.

## Профилактика

Тест «UTF-16 и битый UTF-8 не роняют процесс» (число записей карты, без
get по невалидному ключу — сам get ассертит).
