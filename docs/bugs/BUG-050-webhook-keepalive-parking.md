# BUG-050 — webhook: однопоточный accept паркуется на простаивающем keep-alive соединении

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/bot/webhook.zig` (все respond с keep_alive=false)
- Открыт: 2026-09-10
- Где найдено: код-ревью (std.http.Server.RespondOptions.keep_alive=true по умолчанию)
- Серьёзность: средняя

## Симптом

Терминатор (nginx/caddy) держит upstream-соединения открытыми: после
ответа сервер блокирующе ждёт следующий запрос в receiveHead на том же
сокете — новые соединения (и апдейты Telegram) стоят в backlog до
idle-таймаута терминатора (у nginx — до 60 с латентности). Любой
не закрывающий соединение клиент паркует весь бот.

## Причина

std.http.Server ставит keep-alive по умолчанию; обработка соединений
синхронная, однопоточная.

## Лечение

Отвечать с `keep_alive = false`: соединение закрывается после ответа,
accept-цикл свободен. Telegram ретраев не требует — 200 уже отправлен
до обработки.

## Профилактика

Ручная проверка TC-152 (два параллельных curl: второй не ждёт первого).
