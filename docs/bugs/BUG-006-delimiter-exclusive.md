# BUG-006 — takeDelimiterExclusive не съедает разделитель (Zig 0.15.2)

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: тесты (мини-репро)
- Серьёзность: средняя
- Фикс: `src/net/https.zig` (takeDelimiterInclusive + трим)

## Симптом

Чтение HTTP-строк по `\n` возвращало пустые строки: вторая «строка» была
пустой, хотя в буфере оставались данные.

## Причина

Квирк стандартной библиотеки 0.15.2: `takeDelimiterExclusive` toss-ит
только содержимое, сам разделитель остаётся в потоке (вопреки док-комментарию).
Поймано изолированным репро из четырёх строк.

## Лечение

Все построчные чтения переведены на `takeDelimiterInclusive('\n')` с
ручным `trimRight(u8, line, "\r\n")`.

## Профилактика

Знание зафиксировано в комментарии кода. При апгрейде std — прогнать
мини-репро заново: если починят док-поведение, можно вернуть Exclusive.
