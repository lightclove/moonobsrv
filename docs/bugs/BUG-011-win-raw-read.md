# BUG-011 — сырой stream.read не работает на сокетах Windows

- Статус: ЗАКРЫТ (было ОТКРЫТ, закрыт 2026-09-09)
- Открыт: 2026-09-09
- Где найдено: тесты (фейковый прокси на 127.0.0.1)
- Серьёзность: средняя
- Фикс: `net/socks5.zig`, `db/pg.zig` (интерфейсы Reader/Writer)

## Симптом

Тест SOCKS5-хендшейка падал с `GetLastError(87): Параметр задан неверно`
на ровном месте: и клиент, и фейк-сервер получали ошибку 87 от `ReadFile`.

## Причина

`std.net.Stream.read` на Windows идёт через `ReadFile`, который на сокетах
в этой конфигурации возвращает ошибку 87. Рабочий путь — интерфейсы
`Stream.Reader`/`Stream.Writer` (внутри WSARecv/WSASend).

## Лечение

Весь ввод-вывод сырых протоколов (SOCKS5, PostgreSQL) переведён на
`stream.reader(...)/stream.writer(...)` + `.interface()`. Для Docker
(unix-сокет, Linux-only) оставлены прямые read/write — там это работает
и путь не компилируется на Windows.

## Профилактика

Правило: на Windows — никаких сырых `stream.read` на сокетах, только
Reader/Writer-интерфейсы. Кросс-платформенность сетевого кода держится
тестами с фейк-серверами.
