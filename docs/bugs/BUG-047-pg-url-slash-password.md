# BUG-047 — '/' в пароле URL Postgres даёт PgBadUrl — бот молча уходит в открытый режим

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-10)
- Фикс: `src/db/pg.zig` (parseUrl: база ищется после последнего '@') + тест
- Открыт: 2026-09-10
- Где найдено: код-ревью (доказано зондом: user:p/ss@db → PgBadUrl)
- Серьёзность: средняя

## Симптом

`MOONOBSRV_DB=postgresql://moon:p/ss@db:5432/sky` (сгенерированные пароли
с '/' нередки) → attachDb падает → main логирует «работаю без БД» →
`!store.dbMode()` → бот при заданном TELEGRAM_ACCESS_ID ОТКРЫТ ВСЕМ, единственный
след — строка в логе (тихая деградация безопасности).

## Причина

parseUrl искал первый '/' по всей строке ДО выделения кредов, тогда как
'@' и ':' в пароле обрабатывались через lastIndexOf — приём спецсимволов
был несогласован.

## Лечение

База отделяется первым '/' ПОСЛЕ последнего '@'.

## Профилактика

Тест parseUrl с паролем «p/s». Правило: спецсимволы URL — только через
lastIndexOf-схему от хвоста.
