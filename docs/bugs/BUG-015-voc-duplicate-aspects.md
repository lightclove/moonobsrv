# BUG-015 — VOC: соединения и оппозиции попадают в список аспектов дважды

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/astro/voc.zig` (перебор смещений с учётом симметрии) + регресс-тест в `src/tests.zig`
- Открыт: 2026-09-09
- Где найдено: тесты (злой QA, прогон TC-022/TC-027 из docs/TESTCASES_AAA.md)
- Серьёзность: средняя

## Симптом

В ответе `/voc` (и в `--today`) строки предстоящих аспектов дублируются
дословно, например (3 января 2026):

```
• ☍ оппозиция Венера — 3 января, 11:42
• ☍ оппозиция Солнце — 3 января, 13:04
• ☍ оппозиция Марс — 3 января, 15:39
• ☍ оппозиция Венера — 3 января, 11:42   ← повтор
…
```

Дублируются только соединения (0°) и оппозиции (180°); секстили/квадраты/
трины — по одному разу. Зонд за 60 дней (шаг 6 ч): 228 пар-дублей в
`voc.assess`, 119 дублей строк в тексте `/voc`.

## Причина

`src/astro/voc.zig`, цикл подбора смещений в `assess`:

```zig
for (aspects.all) |asp| {
    const a = asp.angleOf();
    for ([2]f64{ a, -a }) |off| { ... }
}
```

Для соединения `a = 0`, смещения `+0` и `−0` задают одну и ту же функцию;
для оппозиции `a = 180` функции `wrap180(s + 180)` и `wrap180(s − 180)`
тождественны (различаются на 360°, которую съедает wrap180). Оба смещения
находят один и тот же момент, и событие пишется в буфер дважды. Побочный
эффект: дубли расходуют слоты буфера `max_aspects = 24`.

Поймано зондом QA (TC-022 «аспекты: сортировка и уникальность») —
существующие тесты уникальность не проверяли.

## Лечение

Перебирать смещения с учётом симметрии: соединение — только `{0}`,
оппозиция — только `{180}`, остальные аспекты — `{a, −a}` (это два разных
события: например, Луна впереди планеты на 60° и позади на 60°).

## Профилактика

Регрессионный тест в `src/tests.zig`: на серии дат 2026 года убедиться, что
в `assess().aspects` нет пары событий с одинаковыми (body, aspect) и
|Δt| ≤ 2 с, и что в тексте `/voc` нет дословно повторённых строк «• …».
