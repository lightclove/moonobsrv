# BUG-027 — onPollFail: ветка восстановления мертва — «Telegram снова доступен» не приходит, алерт течёт

- Статус: ЗАКРЫТ (был ОТКРЫТ, закрыт 2026-09-09)
- Фикс: `src/main.zig` (`recoverAlert` в успешной ветке runPolling; мёртвая ветка удалена)
- Открыт: 2026-09-09
- Где найдено: код-ревью (злой QA, F-91)
- Серьёзность: средняя

## Симптом

После восстановления связи админ не получает «✅ moonobsrv: Telegram
снова доступен» — никогда. Более того, `alert_pending` не очищается:
при следующем сбое бот повторно шлёт текст ПЕРВОГО алерта каждые 20 с
(даже если причина новая), и буфер, дублированный в page_allocator,
утекает на каждом эпизоде.

## Причина

`src/main.zig:324` инкрементирует `ps.consec_fails` в начале onPollFail,
а ветка восстановления (`else if (ps.consec_fails == 0 and
ps.alert_pending != null)`, строки 375–382) — внутри этой же функции:
условие `== 0` недостижимо. Успешный путь runPolling (`consec_fails = 0`)
про восстановление ничего не знает.

## Лечение

Обработку восстановления перенести в успешную ветку runPolling: после
`consec_fails = 0` при наличии `alert_pending` — отправить «снова
доступен», освободить и обнулить.

## Профилактика

Интеграционный тест цикла не строится юнитом (сеть) — ручная проверка F3
из MANUAL_TESTING.md: после подъёма tor обязан прийти «снова доступен»
ровно один раз.
