Репозиторий: `github.com/lightclove/moonobsrv` (ветка `main`). Версии — semver `MAJOR.MINOR.PATCH`; текущая строка — `pub const version` в [src/runtime.zig](../src/runtime.zig) (оттуда читают `--version`, `/status` и шапку `--help`).

Формат как у rbot (Keep a Changelog + changelog Windows/Android Малыка): сначала **хронология**, затем каталог того, что умеет программа сейчас, затем подробности выпусков.

## Каталог функционала (сейчас = 1.2.2)

У каждого раздела — дата и версия, **когда возможность впервые появилась**. Поздние уточнения — вторая дата рядом, первую не стираем.

### Замысел и форма поставки — с 1.0.0 / 2026-09-09

- Телеграм-бот наблюдений за небом на чистом Zig: вся астрономия считается локально (ряды Meeus, кеплеровские элементы Standish), ни одного внешнего API и зависимостей.
- Один бинарь `moonobsrv.exe` / `moonobsrv`. Тулчейн Zig 0.15.2 вложен в `tools/` (~330 МБ, в `.gitignore`), обёртка `z.cmd` — сборка самодостаточна.
- Релизный профиль `-Drelease`: `ReleaseSmall`, strip, `omit_frame_pointer`, gc-sections, без libc. Пол — TLS-клиент из std (~420 КБ). С 1.0.1 / 2026-09-09 прод — статический linux-musl бинарь, кросс-компилируемый на dev-машине (`-Dtarget=x86_64-linux-musl`): 715 КБ.
- CLI: `moonobsrv --today` (офлайн-сводка), `--webhook-info`, `--help`, `--version`. С 1.0.1 / 2026-09-09 ещё `moonobsrv watch` — хостовый сторож.

### Астроядро — с 1.0.0 / 2026-09-09

- Чистые функции `f64 → f64` без аллокатора (буферы передаёт вызывающий), хаб — `src/astro.zig`.
- Солнце — Meeus 25 (±0.01°). Луна — усечённый ELP2000, 58 членов (±0.05°). Планеты — кеплеровские элементы Standish JPL (угловые минуты, валидны 1800–2050); таблица от Меркурия до Плутона.
- VOC — классика: ингрессии + точные аспекты к шести видимым телам. Лунный день — 30-я часть лунного месяца (элонгация (N−1)·12°). Ретро — станции и пред/пост-тени любой планеты.
- Лунные сутки «от восхода до восхода» — с 1.1.0 / 2026-09-09: русская астрологическая традиция (П. Глоба, массовые календари) рядом с титхи. 1-е сутки — с новолуния до первого восхода Луны, дальше от восхода до восхода, последние обрывает новолуние. Для этого: широта Луны (8 старших членов ELP2000, ±0.05°), эклиптика → экватор, звёздное время Meeus 12.4, восход при h₀ = +0.125° (`astro/rise.zig`), новолуния бисекцией по сырой элонгации. Точность восходов — единицы минут (параллакс средний). Место — `MOONOBSRV_LAT`/`MOONOBSRV_LON`, по умолчанию Москва.
- Монотонность вместо перебора: сепарация Луна–планета и элонгация строго растут, границы ищутся бисекцией по «пиле» wrap180 — шаг скана 29 минут, уточнение до секунд.
- Тесты-якоря по реальным событиям (`src/tests.zig`): затмения 12.08.2026 и 03.03.2026, ретро-Меркурий 2026 (3 окна) и 2027, ретро-Венера 2026, ингрессия Луны в Деву 09.09.2026 22:36 МСК, 28-й лунный день 09.09.2026. С 1.0.1 — ещё протокольные тесты (SOCKS5, PostgreSQL, клавиатуры, стоп-краны): всего 73. С 1.1.0 / 2026-09-09 — новолуния 12.08 и 11.09.2026 (±15 мин к timeanddate), восходы Луны в Москве 8–10.09.2026 (01:23 / 03:01 / 04:35 МСК — минута в минуту с astrostar.ru), сутки 27/28/30 и 24-минутные 30-е сутки 11.09: всего 77. С 1.2.0 / 2026-09-09 — регрессии на 23 бага QA-прогона (уникальность аспектов VOC, несуществующие даты, tzLabel, SQL заявки, буфер курсора, кламп визарда, idle-статистика и др.): всего 91. С 1.2.1 / 2026-09-10 — регрессии ночной вахты (Labels:null, UTF-16 env, пароль с '/', IPv6-SOCKS5, тени ретро, высокие широты восходов и др.): всего 99.

### Режимы: polling, webhook, сторож — с 1.0.0 / 2026-09-09; сторож — с 1.0.1 / 2026-09-09

- **Polling (по умолчанию)**: long polling, `MOONOBSRV_POLL_TIMEOUT`. При старте снимает webhook (`deleteWebhook`), чтобы режимы не конфликтовали.
- **Webhook**: включается `MOONOBSRV_WEBHOOK_URL`; бот слушает HTTP на `MOONOBSRV_LISTEN` за TLS-терминатором (серверного TLS в std нет), путь из URL + заголовок `X-Telegram-Bot-Api-Secret-Token` против `MOONOBSRV_WEBHOOK_SECRET`. Общий `dispatch.zig` — команды одни и те же в обоих режимах.
- **Сторож `moonobsrv watch`** — с 1.0.1 / 2026-09-09: отдельный процесс для systemd; только `sendMessage` (иначе 409 с ботом). Смотрит docker-демон, контейнеры bot/db/tor, Telegram через Tor-socks, диск ≥85%, CPU ≥80 °C, питание, sshd. Дебаунс: состояние должно повториться дважды, дальше только переходы.

### Состояние: state.json и Postgres — с 1.0.0 / 2026-09-09; Postgres — с 1.0.1 / 2026-09-09

- `data/state.json`: атомарная запись (tmp + rename), схема версионируется полем `v`, при первом запуске инициализируется текущим небом — спама «переходов» при старте нет. Небесные флаги живут здесь и с БД.
- Postgres (`MOONOBSRV_DB`) — с 1.0.1 / 2026-09-09: собственный клиент wire-протокола v3 без зависимостей — startup, trust/cleartext/md5, простой протокол Q, текстовый формат; SCRAM нет (контейнер БД на trust/md5 в изолированной сети compose, хост-порт наружу не публикуется). Одно соединение на процесс, переподключение при обрыве, таймауты на сокете.
- Схема: `app_user` (whitelist + флаг уведомлений), `layer_sample` (сэмплы слоёв, retention 400 дней), `bot_kv` (курсор), `tg_inbox` (дедуп апдейтов, retention 90 дней).
- Пустой `MOONOBSRV_DB` — режим без БД: подписчики в `state.json`, whitelist отключён, `/idle*` отвечает «нет данных».
- Сэмплы слоёв — раз в минуту, битовая маска (pg/tg/tor/wan/docker/disk); формулы и пороги перенесены из rbot (гэп 150 с, инциденты по падающему фронту).

### Админский контур — с 1.0.1 / 2026-09-09 (порт из rbot)

- `TELEGRAM_ACCESS_ID` включает контур; без него админских команд нет, бот открыт всем — режим разработки.
- Доступ: whitelist в Postgres; новый человек → админу заявка с кнопками «Пустить / Отклонить» (`acl:allow/deny:ID`); denied молчит до `/start`, повторные заявки не спамят.
- `/monitor` — живой срез слоёв (процесс, Postgres, Telegram, Tor, WAN, Docker, диск, RAM, CPU, питание, sshd).
- `/restart*` — план рестарта с анти-бутлупом: ACK `getUpdates` до docker-restart, маркер «уже перезапускались», replay-фильтр по дате сообщения, пачка обновлений просматривается целиком. Telegram/WAN/Docker/диск отвечают «нельзя» — это не процессы стека.
- `/reset` `/hardreset` — стоп-кран очереди: подтвердить пачку Telegram целиком; `/hardreset` + один рестарт бота.
- `/idle*` — простой слоёв за окно по сэмплам; окна час/3/5/8/12/24 ч и календарные день/ночь/неделя/месяц/год; промежутки «с … по …».
- `/users`, `/revoke`.
- Docker Engine API через `/var/run/docker.sock` сырым HTTP/1.0 — без библиотек.

### Гид и кнопки — с 1.0.1 / 2026-09-09

- `/wizard`: «книга» слайдов без состояния — позиция живёт в `callback_data` (`wiz:p:N`), каждый нажим редактирует то же сообщение; оглавление 8/стр и прогресс-бар. 22 слайда по астрологии + 3 админских (вставка после «Шпаргалки»).
- Callback-роутер (`bot/cb.zig`): `wiz:*` (гид), `menu:*` (меню команд), `acl:*` (заявки). Каждый колбэк получает `answerCallbackQuery` — иначе на кнопке останутся «часики».
- Меню быстрых команд — чего нет в rbot: Луна/Меркурий/лунный день/планеты/подписка кнопками.

### Сеть через Tor — с 1.0.1 / 2026-09-09

- `MOONOBSRV_TOR=socks5://tor:9050`; синонимы окружения: `HTTPS_PROXY` / `https_proxy` / `ALL_PROXY` / `all_proxy` (схемы socks5/socks5h).
- Собственный SOCKS5-клиент (RFC 1928): CONNECT без аутентификации, адрес цели — всегда домен (DNS резолвит Tor, семантика socks5h); кадры — чистые функции, тестируются байт-в-байт.
- Собственный HTTPS-клиент: TLS 1.3 из `std.crypto` поверх TCP или SOCKS5, HTTP/1.1 keep-alive на одном соединении — вместо `std.http.Client`, который не умеет SOCKS. Таймауты на сокетах (30 с прокси / 75 с данные), один тихий ретрай на обрыв.
- Два соединения: основное (при заданном прокси — через Tor) и direct для алертов.
- Две тонкости, пойманные на проде: буфер сокет-писателя ≥ `tls.min_buffer_len` (~17 КБ, меньше — UB в релизе), и flush TLS-писателя надо вытолкнуть flush'ем сокет-писателя.

### Контейнеры и деплой — с 1.0.1 / 2026-09-09

- `docker-compose.yml` (bot + postgres:16-alpine, порт 5433 только на localhost) и `docker-compose.prod.yml` (tor-слой, БД без хост-порта, `MOONOBSRV_TOR=socks5://tor:9050`).
- `ci/tor/` — свой образ Tor: SocksPort 9050 для сети compose, healthcheck по бутстрапу 100% на control-порту; obfs4-мосты (провайдер душит прямые соединения) — `torrc` не коммитится, `torrc.example` — шаблон.
- `Dockerfile`: alpine + ca-certificates + статический musl-бинарь из `dist/`; на проде ничего не собирается и не скачивается. Healthcheck контейнера — свежесть heartbeat-файла `/tmp/moonobsrv.hb`.
- `deploy.cmd` → `ci/deploy.ps1`: тесты → кросс-сборка linux-musl → tar → scp → `ci/remote-apply.sh` (бэкап БД, compose up, ожидание бота); цель и ключ — из `netaccess/.credentials` и `~/.ssh/id_ed25519_arch`.
- Прод: Arch `192.168.31.11:22022`, `~/Work/moonobsrv`; токены только в `.env` на проде (0600).
- `scripts/backup.sh` — pg_dump | gzip в `backups/`.

### Надёжность — с 1.0.1 / 2026-09-09

- Watchdog: heartbeat пишется каждый цикл; тишина > 300 с → trap, Docker поднимет процесс (healthcheck контейнера — тот же файл).
- Guard `getUpdates`: серия из 3 неудач отличает Tor от «хост без WAN», рестарт Tor с кулдауном 90 с; алерты админу не чаще раза в 600 с, повтор недоставленного каждые 20 с, восстановление — отдельное сообщение. Алерты идут direct-каналом в обход прокси.
- Dedup апдейтов: `tg_inbox`, inflight-«яд» (процесс умер посреди апдейда — апдейт пропускается), offset-курсор в файле и `bot_kv` — повторная выдача после рестарта не дублирует команды.
- Бэкофф на ошибки опроса: 2/2/4/8/15/30 с. 409 (один токен = один polling) — выход с кодом 2.

### Ограничения этой линии

- Один инстанс на токен (иначе getUpdates вернёт 409 / webhook будет перезаписан).
- Тексты ответов ≤ 4096 символов — обрезаются по границе UTF-8.
- Webhook требует TLS-терминатор; SCRAM-аутентификация Postgres не поддерживается (контейнер БД настраивается на trust/md5).
- Рельсы ретро-планет точны до угловых минут (кеплеровские элементы), ингрессии/аспекты — до минут модельного времени (ΔT игнорируется).
- `TELEGRAM_ACCESS_ID` на проде пока не задан — бот в открытом режиме (id виден в `/status`).
