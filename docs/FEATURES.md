## 1. Границы системы

`moonobsrv` — телеграм-бот наблюдений за небом на чистом Zig 0.15.2 без
внешних зависимостей. Вся астрономия считается локально. Внешние интеграции
ровно две: Telegram Bot API (напрямую или через Tor) и опциональный Postgres.

Режимы запуска одного бинаря:

| Режим | Условие | Что делает |
| --- | --- | --- |
| long polling (по умолчанию) | задан `TELEGRAM_TOKEN`, нет `MOONOBSRV_WEBHOOK_URL` | сам опрашивает Telegram |
| webhook | задан `MOONOBSRV_WEBHOOK_URL` | слушает HTTP на `MOONOBSRV_LISTEN`, регистрирует webhook |
| хостовый сторож | подкоманда `watch` | отдельный процесс для systemd: алерты админу о слоях |
| CLI-утилиты | `--today` / `--webhook-info` / `--help` / `--version` | печать и выход |

Ограничения системы: один инстанс на токен (иначе getUpdates вернёт 409 и
процесс завершится с кодом 2); ответы ≤ 4096 симв. (обрезаются по границе
UTF-8); тексты дат — русские, часовой пояс вывода задаётся числом часов.

## 2. Астроядро

Чистые функции `f64 → f64` без аллокатора (хаб `src/astro.zig`), буферы
передаёт вызывающий. Ядро не знает ни о боте, ни о сети.

### F-01. Время (astro/time.zig)

- `jdFromUnix`/`unixFromJd` — Unix ↔ юлианский день (JD), точность округления до секунды.
- `centuriesSinceJ2000` — юлианские столетия от J2000.
- `gmstDeg` — среднее гринвичское звёздное время в градусах (Meeus 12.4), не заворачивается.
- `unixUTC`/`daysFromCivil` — гражданская дата UTC → Unix (алгоритм Хиннанта), для якорей.

### F-02. Углы и решатели (astro/angles.zig)

- `wrap360`/`wrap180` — нормализация углов; `wrap180` даёт диапазон (−180, 180].
- `sinD`/`cosD` — тригонометрия от градусов.
- `nextZero`/`prevZero` — следующий/предыдущий переход через ноль «пилы»
  `wrap180(f(t))`: скан шагом 0.02 сут (~29 мин) + бисекция (28 итераций,
  точность до секунд). Контракт: внутри периода функция непрерывна и возрастает.
- `bisectRising` — бисекция строго возрастающей функции (34 итерации).
- `bisectSign` — бисекция непрерывной функции по смене знака (40 итераций).

### F-03. Солнце (astro/sun.zig)

Видимая эклиптическая долгота, Meeus 25, ±0.01°. Функция непрерывна, не
нормируется — для монотонных решателей.

### F-04. Луна (astro/moon.zig)

- `longitudeRaw` — непрерывная (невернутая) эклиптическая долгота: усечённый
  ELP2000 (Meeus 47, табл. 45.A), 58 старших членов, ±0.05°; долгота строго растёт.
- `latitude` — широта Луны, 8 старших членов, ±0.05° (нужна восходам).
- `fundamentals` — аргументы ряда (lp, D, M, M', F, E), не заворачиваются.

### F-05. Планеты (astro/planets.zig)

- Тела: mercury…pluto (+ sun как отдельная формула). Геоцентрическая долгота
  по кеплеровским элементам Standish (JPL, 1800–2050, точность — угловые
  минуты): heliocentric → вычитание Земли → atan2 → линейная прецессия к
  эклиптике даты → wrap360.
- Кеплер решается Ньютоном (12 итераций) от начального E = M.
- `classical` — шесть видимых тел (Солнце…Сатурн) для VOC.

### F-06. Аспекты (astro/aspects.zig)

Пять птолемеевских аспектов: соединение 0°, секстиль 60°, квадрат 90°,
трин 120°, оппозиция 180°. Русские названия и глифы.

### F-07. Холостая Луна — VOC (astro/voc.zig)

`assess(now, buf)` возвращает статус:

- `sign` — текущий знак по долготе Луны (12 знаков по 30°, enum с русскими
  склонениями: именительный/предложный/винительный);
- `sign_entered`/`ingress` — моменты входа в текущий знак и выхода в следующий
  (бисекция по «пиле», окно ±2.6 сут);
- `progress_pct` — пройдено процентов знака;
- `aspects` — все точные аспекты Луны к шести классическим телам внутри
  текущего знака, по возрастанию времени (сортировка вставками, буфер 24);
- `is_voc` — истина, когда аспектов после текущего момента нет;
- `voc_started` — последний аспект ≤ now или вход в знак; `voc_last_aspect` — он же.

Определение: Луна холостая с момента последнего точного аспекта в знаке до
ингрессии в следующий знак. Если в знаке аспектов нет вовсе — холостая с
момента входа в знак.

### F-08. Лунные дни — титхи (astro/lunday.zig)

- `assess(now)` — номер дня 1..30: элонгация Луна−Солнце (непрерывная,
  строго растущая ≥ ~10.5°/сутки) пересекает (N−1)·12°. Границы дня —
  бисекцией (±1.6 сут). Дополнительно: знак Луны, освещённость
  (1−cos(элонгация))/2·100%, фаза (`phaseName` по элонгации: новолуние
  <15° и >345°, молодая, первая четверть, растущая, полнолуние, убывающая,
  последняя четверть, старая).
- `lastNewMoonJd`/`nextNewMoonJd` — последнее/ближайшее новолуние (уровень
  360°·k сырой элонгации, окно 31 сут).

### F-09. Восход Луны (astro/rise.zig)

- `altitude(obs, jd)` — геоцентрическая высота центра Луны над горизонтом:
  эклиптические координаты → экваториальные (Meeus 13), часовой угол через
  GMST + долготу места, высота через широту места.
- `nextRise(obs, t0)` — ближайший восход строго после t0 в пределах ~31.4 ч:
  скан шагом 0.01 сут (14.4 мин) + бисекция по пересечению h₀ = +0.125°
  (0.7275·π − 34′ — рефракция и средний параллакс). null — восхода нет
  (полярные широты). Наблюдатель: `MOONOBSRV_LAT`/`LON` (по умолчанию Москва).
  Точность — единицы минут.

### F-10. Лунные сутки «от восхода» (astro/lunday_rise.zig)

`assess(now, obs)` — русская традиция: 1-е сутки — с новолуния до первого
восхода Луны; каждые следующие — от восхода до восхода; последние (29-е или
30-е) обрывает следующее новолуние. null — система неприменима (Луна не
восходит). Сутки длиннее титхи (~24–26 ч), к концу месяца отставание 1–2 номера.

### F-11. Ретроградность (astro/retro.zig)

- `isRetro(body, now)` — знак скорости долготы (центральная разность, шаг ±0.25 сут).
- `upcoming(body, from, out[4])` — окна ретро-периодов начиная с from (первое
  может уже идти — станция ищется назад до 25 сут). Окно: `start` (станция
  директ→ретро), `end` (ретро→директ), `pre_shadow` (последний проход по
  градусу будущей станции директа до ретро), `post_shadow` (возвращение к
  градусу станции ретро после). Горизонт поиска — 420 сут, максимум 4 окна.
- Станции: скан скорости шагом 1 сут + бисекция по смене знака.

## 3. Команды астрономии

Все команды доступны всем пользователям; аргумент-дата необязатела: без
аргумента «сейчас», с аргументом — полдень указанного дня в зоне `MOONOBSRV_TZ`.

### F-20. /voc (+/void, /холостая)

Статус VOC на момент: «🌒 Луна не холостая / 🌚 Луна сейчас ХОЛОСТАЯ», знак и
процент прохождения, предстоящие аспекты (до 6 строк «глиф аспект тело — дата»),
ближайший холостой период (после последнего аспекта до ингрессии) либо, в
холостом режиме, время начала периода (после какого аспекта) и вход в следующий
знак. В холостом режиме — совет не начинать важных дел.

### F-21. /mercury (+/retro, /меркурий)

«☿ Меркурий РЕТРОГРАДЕН / директен»: текущее окно с остатком времени,
пост-тень, следующий ретро-период; либо ближайший ретро-период с пред- и
пост-тенями и окно после него (до 2 окон).

### F-22. /day (+/lunday, /moon, /луна)

Две системы рядом: «🗓 N-й лунный день (титхи)» с началом и концом, и
«🌄 По восходам Луны (55.8° с.ш., 37.6° в.д.) — N-е лунные сутки» с началом и
концом. Подвал: знак Луны со глифом, освещённость (целые %), фаза; пояснение
разницы систем с градусом элонгации начала текущего титхи ((N−1)·12°).

### F-23. /planets-семейство: /venus /mars /jupiter /saturn

«глиф Имя: глиф-знака в Знаке, директное/ретроградное движение»; для директных —
ближайший ретро-период; для ретроградных — дата станции директа.

### F-24. Аргументы-даты

Форматы: `ДД.ММ`, `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`; год 1900..2200; без года —
текущий. Полдень местного дня. Невнятный аргумент → подсказка «Не понял дату…»
и команда не выполняется.

## 4. Сервисные команды

### F-30. /start

HTML-приветствие + кнопки: «🚀 Открыть обучающий гид», «📚 Оглавление», «☰ Меню
команд». В тексте — количество слайдов гида (для админа — с админскими).

### F-31. /help (+/commands)

Меню команд по группам (HTML) с теми же кнопками.

### F-32. /status (+/stat)

Версия бота, id отправителя (для настройки `TELEGRAM_ACCESS_ID`), аптайм,
число подписчиков, период проверки неба, метка часового пояса («МСК», «UTC»,
«UTC+5:30»).

### F-33. /subscribe (+/sub, /подписка), /unsubscribe (+/unsub, /отписка)

Управление уведомлениями; повторная подписка идемпотентна, отписка
не подписанного — «Вы ещё не были подписаны».

## 5. Уведомления и подписки

### F-40. Ватчеры (фоновый поток)

Раз в `MOONOBSRV_CHECK_INTERVAL` (60 с) сравнивает небо с сохранённым
состоянием; переходы рассылаются подписчикам. Три семейства событий:

- **VOC**: начало (🌚… последний аспект, знак, до входа в какой знак и когда) и
  конец (🌝 Луна вошла в … — можно браться за дела);
- **Меркурий**: стал ретроградным (окно), стал директным (+пост-тень);
- **планеты** (/venus…/saturn): начало/конец ретроградности;
- **лунный день**: «🌙 Начался N-й лунный день (титхи)», конец, номер по
  восходам, знак и фаза.

При первом запуске состояние инициализируется текущим небом (bootstrap) —
фальшивых «переходов» нет. Работает одинаково в polling и webhook.

## 6. Обучающий гид /wizard

### F-50. Слайды

Книга из 22 пользовательских слайдов + 3 админских (вставляются после
«Шпаргалки», видит только владелец). Под каждым слайдом — «⏮ Назад / Далее ⏭»,
прогресс-бар из квадратиков, номер страницы. Состояние не хранится: позиция
живёт в `callback_data` (`wiz:p:N`), каждое нажатие редактирует то же сообщение.
Слайды ≤ 4096 символов (проверяется тестом), пользовательские не содержат
админских команд (проверяется тестом).

### F-51. Оглавление и закрытие

«📚 Оглавление» — по 8 тем на страницу с навигацией по страницам; кнопка
«✖ Закрыть». Прогресс-бар только на слайдах, не в оглавлении.

## 7. Меню-кнопки и callback-роутер

### F-60. Меню быстрых команд

Рядок кнопок «Луна сейчас / Меркурий / Лунный день / Планеты / Подписка» под
/start, /help и неизвестными командами (`menu:cmd:/voc` и т.д.): нажатие
выполняет команду и редактирует сообщение ответом.

### F-61. Callback-роутер (bot/cb.zig)

Префиксы `wiz:*` (гид), `menu:*` (меню), `acl:*` (заявки: `acl:allow:ID`,
`acl:deny:ID`). Каждый колбэк получает `answerCallbackQuery` (иначе на кнопке
останутся «часики»). `callback_data` ≤ 64 байт (проверяется тестом).

## 8. Доступ: whitelist и заявки

### F-70. Закрытый режим

Включён, когда заданы `TELEGRAM_ACCESS_ID` и БД. Новый пользователь пишет
любую команду → админу карточка (кто, id, что написал) с кнопками
**Пустить / Отклонить**; «Пустить» → человек в whitelist и получает
приветствие; «Отклонить» → молчание до следующего `/start`. Повторные заявки
не спамят (pending-механизм). `/users` — список, `/revoke <id>` — отзыв.
Без БД или без админ-id бот открыт всем, админские команды отвечают отказом.

## 9. Админский контур

### F-80. /monitor

Живой срез слоёв: процесс, Postgres, Telegram, Tor, WAN (пробы 1.1.1.1/8.8.8.8),
Docker, диск, RAM, CPU-температура, питание, sshd.

### F-81. /restart-семейство

`/restart` — всё сразу: postgres → tor (ожидание до 48 с) → бот; `/restartbot`
`/restartpostgres` `/restarttor` — по слою (Docker Engine API сырым HTTP/1.0
через /var/run/docker.sock); `/restarttelegram` `/restartwan` `/restartdocker`
`/restartdisk` — честный отказ («не процесс стека»). Анти-бутлуп: ACK
(getUpdates timeout=0) до рестарта, replay-фильтр (команды старше процесса
пропускаются), кулдаун рестартов 90 с, маркер «уже перезапускались».

### F-82. /reset (+/flush), /hardreset (+/hard) — стоп-краны

Пачка обновлений просматривается целиком ДО обработки: если в хвосте стоп-кран —
вся пачка отбрасывается, подтверждается Telegram (ACK), `/restart` из пачки не
выполняется; пользователю — текст «сброшено N апдейтов». `/hardreset` — плюс
один docker-restart контейнера бота. Аптайм при /reset не сбрасывается.

### F-83. /idle* — дневник простоев

Окна: hour, 3, 5, 8, 12, 24 ч и календарные day (с полуночи), night (22–8),
week (с понедельника), month (с 1-го), year (с 1 января); опечатки `/idel*`
приняты. По сэмплам слоёв (раз в минуту, битовая маска pg/tg/tor/wan/docker/
disk + проценты) считает: жив ли слой X% времени, сколько не дышал суммарно,
промежутки «с … по …». Без БД — «нет данных».

## 10. Сторожа и самовосстановление

### F-90. Watchdog

Heartbeat-файл `/tmp/moonobsrv.hb` пишется каждый цикл; молчание > 300 с →
@trap(), Docker поднимает контейнер (healthcheck — тот же файл, >300 с =
unhealthy). Стартовая отсрочка (grace) от ложных срабатываний.

### F-91. Guard getUpdates

3 подряд неудачи: классификация Tor vs WAN (пробы socks/wan), авто-рестарт
tor-контейнера с кулдауном 90 с, алерт админу direct-каналом (в обход прокси),
повтор недоставленного каждые 20 с, не чаще раза в 600 с; восстановление —
отдельное «снова доступен». Бэкофф на ошибки опроса: 2/2/4/8/15/30 с.
409 — выход с кодом 2.

### F-92. Dedup апдейтов

`tg_inbox` + offset-курсор в файле и БД; inflight-«яд» (процесс умер посреди
апдейта — при старте апдейт пропускается и подтверждается).

### F-93. hostwatch (`moonobsrv watch`)

Отдельный процесс: раз в минуту — docker-демон, контейнеры bot/db/tor,
Telegram через Tor, диск ≥85%, CPU ≥80 °C, питание, sshd. Дебаунс «два
одинаковых снимка подряд», алерты только на переходы, первое стабильное
состояние — сводка. Только sendMessage.

## 11. Хранение: state.json и Postgres

### F-100. state.json

`data/state.json`: небесные флаги (voc_active, mercury_retro, …, lunar_day) —
всегда JSON, даже с БД; подписчики в режиме без БД. Атомарная запись
(tmp + rename), схема с полем `v`.

### F-101. Postgres (`MOONOBSRV_DB`)

Собственный клиент wire-протокола v3: startup, trust/cleartext/md5, простой
протокол Q, текстовый формат; SCRAM нет. Схема: `app_user` (whitelist+флаг
уведомлений), `layer_sample` (сэмплы, retention 400 дней), `bot_kv` (курсор),
`tg_inbox` (дедуп, retention 90 дней). Одно соединение, тихий ретрай на обрыв,
таймауты на сокете. Пустой URL — режим без БД.

## 12. Сеть

### F-110. SOCKS5-клиент (RFC 1928)

CONNECT без аутентификации; адрес цели — всегда домен (DNS резолвит прокси,
семантика socks5h). Кадры — чистые функции, байт-в-байт тесты.

### F-111. Свой HTTPS-клиент

TLS 1.3 (std.crypto) + HTTP/1.1 keep-alive поверх TCP или SOCKS5. Таймауты
30 с (прокси) / 75 с (данные), один тихий ретрай на обрыв. Буферы сокет-писателя
≥ tls.min_buffer_len (~17 КБ); после flush TLS-писателя — flush сокет-писателя.
Два соединения: основное (через Tor) и direct для алертов.

### F-112. Webhook

HTTP-сервер на `MOONOBSRV_LISTEN` за TLS-терминатором; путь из URL; заголовок
`X-Telegram-Bot-Api-Secret-Token` сверяется с `MOONOBSRV_WEBHOOK_SECRET`.
Dispatch общий с polling. При старте polling-режима зарегистрированный webhook
снимается (deleteWebhook).

## 13. CLI-утилиты

### F-120. --today

Офлайн-сводка на сейчас в консоль без сети: блок VOC, блок Меркурия, блок
лунного дня (обе системы). Выход до проверки токена.

### F-121. --version, --help, --webhook-info

`--version` — строка `runtime.version`; `--help` — usage с перечнем переменных
окружения; `--webhook-info` — JSON getWebhookInfo (нужен токен).

### F-122. Запуск без токена

Сервисный режим без `TELEGRAM_TOKEN` — понятная ошибка в stderr и
`error.NoToken`.

## 14. Конфигурация

### F-130. Приоритет и разбор

Реальные переменные окружения → `.env` (рядом с exe или в cwd, или путь из
`MOONOBSRV_ENV`) → дефолты. Синонимы: `TELEGRAM_API_TOKEN`, `HTTPS_PROXY`/
`https_proxy`/`ALL_PROXY`/`all_proxy`. `parseSocks`: схемы socks5/socks5h
(регистронезависимо), `user:pass@` отбрасывается, путь отбрасывается, порт ≠ 0.

### F-131. Переменные

| Переменная | Дефолт | Смысл |
| --- | --- | --- |
| `TELEGRAM_TOKEN` | — | токен Bot API (обязателен в сервисном режиме) |
